Remote drives: what is free on your other machines

The places panel at its default 240 px. Under Remote, each machine you reach through a remote folder (sftp://homelab) can also show its drives. Folded, a machine is one row: a strip with one segment per drive, and a line saying what is free on each. Unfolded, its drives are drawn as the local ones under Devices, and clicking one opens that folder on the machine.

Why it looks like this

  • Where you already go: the machines are the remote places you already open, so there's no second list of machines to keep. A remote place without drives looks as it does today.
  • One row, every drive: the strip answers "is anything filling up?" for all your machines in one glance. The words under it give the figures, so it never relies on colour alone.
  • Same drawing as local drives: unfolded, a remote drive is drawn like one under Devices, with the same bar, the same red from 90 %, the same units from Settings.
  • Honest about age: the figures always say when they were read. An unreachable machine keeps its last ones, faded, rather than a blank.

How the figures would be read (a decision for the maintainer)

  • Today: remote folders are kio-fuse mounts (D-004), and Rustphin itself opens no network connection (R-108, D-018). Not checked yet: whether a kio-fuse mount passes on the remote drive's size. If it does, Rustphin can read it as it reads a local drive's, and nothing below is needed. If it doesn't, the figures need another way.
  • Proposed: the machine's own ssh. Rustphin would run ssh -o BatchMode=yes homelab df … for the chosen drives, and findmnt once for the set-up list. Your ~/.ssh/config, keys and agent are used as they are; BatchMode means it never asks for a password and fails instead. The connection is made by ssh, not Rustphin, as with kio-fuse. Still, it is a feature that reaches the network, which D-018 says reopens the decision, so it needs your go-ahead and a new decision record.
  • Alternative: KDE's KIO. KIO's sftp worker can report a remote drive's free space. That needs Rustphin to link KF6 KIO, a new dependency, and still makes a connection on Rustphin's behalf.
  • Kept local: the chosen drives and the last figures read would be stored in Rustphin's own config, never in KDE's places file (D-008), and listed in PRIVACY.md.
