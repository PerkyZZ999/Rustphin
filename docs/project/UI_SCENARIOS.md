# UI scenarios

Replayable checks of the running application, driven by an agent through the kwin-mcp tools. Run them after any change to the interface (`crates/rustphin`: QML in `crates/rustphin/qml`, Rust objects in `crates/rustphin/src`, the C++ shell in `crates/rustphin/cpp`), and record the result in VALIDATION.md.

The expected texts come from the code: keys from the command table (`crates/rustphin-view/src/commands.rs`, also listed in Settings, Shortcuts), menus from `menu.rs` and `place_menu.rs`, notices from `operations.rs` and `operation_board.rs`, questions from `questions.rs`, pane wording (empty and error states, status line) from `pane.rs`, all in `crates/rustphin-view/src`. When a scenario and the code disagree, the scenario is marked **Needs replay** or **Known gap** rather than rewritten to whatever the code does (see "Replay status on the Qt interface"). Some IDs are used twice (T1–T6 for tabs and for the title bar, P1–P2 for settings and for performance); name the section with the ID when recording a result.

## Setup

1. Build. A debug build is what most scenarios use: `cargo build --package rustphin` gives `target/debug/rustphin`. `rust-tc build` gives the release binary `target/release/rustphin` (needed for L1, I12 and the performance checks). The administrator stand-in is an example of the platform crate: `cargo build --package rustphin-platform --example fake_admin_helper`.
2. Create the fixture in a new scratch directory (never in the user's files): `tests/ui/make-fixture.sh <dir>`. Scenarios U1 and U2 change it, so use a fresh one afterwards. For the mockup scene use `tests/ui/make-mockup-home.sh <isolated home>` (it refuses any path outside `/tmp`). Every other fixture below is generated by hand in a scratch folder or the isolated home, as each section says.
3. Start an isolated session: `session_start` with `app_command` = `target/debug/rustphin <dir>`, `isolate_home: true`, `screen_width: 1280`, `screen_height: 800`.
4. Wait for a screenshot showing the window before sending input; a debug build can take ten seconds or more to show its window, and a screenshot of a few KB means nothing is on screen yet, not that the app crashed.

Environment variables for test launches:

| Variable | Effect |
|---|---|
| `QT_LINUX_ACCESSIBILITY_ALWAYS_ON=1` | Exposes the window over AT-SPI, so `find_ui_elements` finds entries, buttons and dialogs by name |
| `QT_FORCE_STDERR_LOGGING=1` | QML and Qt warnings go to the app's stderr instead of the journal |
| `RUSTPHIN_LOG=debug` | Rustphin's own log level (stderr) |
| `RUSTPHIN_OPAQUE=1` | Forces the opaque theme (any value but `0`) |
| `RUSTPHIN_ADMIN_BUS=session` | Administrator mode looks for the helper on the session bus, where the stand-in runs (AD1–AD9) |
| `RUSTPHIN_FRAME_LOG=1` | Logs a "first entries" line for each folder opened |
| `RUSTPHIN_SCROLL_BENCH=1` | Also scrolls the list for 1,200 frames and logs a "scroll benchmark result" line |

Notes for the agent:

- Without AT-SPI, observe with screenshots and act by keyboard or coordinates.
- With the 1280×800 screen the 1000×700 window (minimum 480×320) is centred. From the top: Rustphin's own 36 px title bar, one toolbar across the window (shield, Back, Forward, Up, Reload, location, New, terminal, View, Split, Show hidden, Filter, Actions; TB10), then the places panel on the left and, beside it, the tab strip (always shown, with "+"), the column headings and the list: 32 px per row at the default zoom. Re-read a screenshot before clicking by coordinates.
- Spell punctuation keys literally: `ctrl+=`, `ctrl+-`, `ctrl+shift+,` (names such as `equal`, `minus` or `comma` send nothing); use lower-case function keys such as `shift+f10`, and `Page_Up`/`Page_Down`.
- Context menus are Qt menus: they open with nothing highlighted, so the first Down reaches the first row, and Down skips disabled rows (such as Paste with nothing to paste).
- Drags need waypoints with pauses of about 100 ms and a short last move before the release. Holding a modifier during a drag (`keyboard_key_down`) is refused in this environment, so G2, G3 and the Ctrl/Shift drop shortcuts cannot be replayed here.
- In the user's Dolphin Ctrl+V is an ambiguous shortcut; paste into Dolphin through its context menu.
- Isolated sessions offer blur, so Rustphin shows its glass theme there unless `RUSTPHIN_OPAQUE=1` is set or Settings says Opaque (before W-146c it asked KWin too early and always started opaque, so earlier pixel measurements are of the opaque theme). The theme is chosen when the first window is made, and again whenever the settings change or a window becomes the active one. Colours may also shift between screenshots there; judge colour by the tokens and their contrast tests. Icons use the `breeze-dark` theme when the session names none.
- The isolated session shares the machine's system bus: the Devices section lists the real drives and the trash menu lists their trashes. Never click a device card, or open its drive menu, and never open another volume's trash, unless Rustphin was launched against the stand-in UDisks2 on a private system bus (DV1–DV6).
- KDE adds its built-in places (Home, Trash, Network…) to `user-places.xbel` the first time one of its applications reads a file without them, so the file changes under Rustphin right after Dolphin starts in a fresh home.
- Rustphin keeps running after its last window closes (W-110) and later launches hand over to it. Each isolated session has its own session bus, so a test Rustphin never hands over to the maintainer's.
- Stop test instances by PID or exact path (`pkill -f target/debug/rustphin`), never `pkill -x rustphin`, which also ends the maintainer's own Rustphin. Stop the session when done. Before deleting the fixture run `chmod 755 <dir>/locked`.
